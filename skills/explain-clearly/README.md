# explain-clearly

> **让读者用最省力的方式看懂** —— 先诊断读者卡在哪里，再选最省力的介质：从受控文字，到图、
> 交互网页、讲解视频、可丢弃小工具，共五级；附 ASD-STE100 受控英语（Issue 9）的完整实现。

## 解决什么问题

一个东西讲不清楚，通常不是「话说得不够多」，而是两件事里至少有一件没做对：**没弄清读者卡
在哪里**，或者**用了不适合这个内容的介质**。本技能把这两件事连成一条线：

- **诊断在前**：术语不认识、看不出组成关系、不清楚步骤、缺因果中间环节、想观察条件变化——
  先找到卡点，再决定用文字、图、网页还是视频。
- **选级在后**：给出五级阶梯的**升维判据**与**降级判据**，以及每级的质量底线，而不是
  「多配几张图」的泛泛建议。
- **保真到底**：介质可以换，事实不能变。数字、单位、比较对象、归因、否定、范围、时间、前提
  和不确定性全部保留；不补造未知的主体或原因，不把相关性写成因果；图示的每条边、交互的每个
  计算都要能追溯到来源或明确的教学假设。

另外，本技能内置 **ASD-STE100 Simplified Technical English（Issue 9, 2025）的完整实现**：
Part 1 全部 9 节 53 条写作规则 + Part 2 受控词典机制（875 核准词 / 1274 未核准词，
附 244 条高频替换表），并配三个可执行检查脚本。这使「写出让读者不必重读的文字」从
文风建议变成可机械检查的硬约束。

## 何时触发

- **帮我看懂**：`帮我看懂`、`这个过程画出来`、`改变这个条件会怎样`、`还是没懂`；
- **讲给别人**：`讲清楚`、`讲解一下`、`画个图`、`做可视化`、`做个讲解网页`、`做个讲解视频`；
- **受控写作**：写**操作手册、维修手册、SOP、安全规程**或需翻译的技术文档；用户点名
  `ASD-STE100`、`受控语言`、`简化这段英文`、`检查这段英文有没有违规`。

**不触发**：结论唯一、无结构、无争议的简单问题——直接答（R0），够用就不要升；简单措辞修改
（如「改得礼貌一点」）只做改写，不做完整流程。

## 典型用法

> 「帮我看懂这份材料，检查通过是不是就能相信结果？」
> 「把这套算法的思路给我讲清楚，别只扔一段文字。」
> 「这个概念画个图 / 做个能拖动的网页 / 剪个两分钟的讲解视频。」
> 「还是没懂，格式没问题为什么解释会错？」
> 「帮我写一份操作规程，要求符合受控英语。」
> 「检查这段英文有没有违反 ASD-STE100。」

工作流：诊断卡点 → 判级（并说明理由）→ 对齐事实与限定 → 先把文字写成受控风格并跑检查脚本
→ 按对应 reference 的硬约束造介质 → 验证 → 交付。各级不是互斥的，是**叠放**的——网页的
文案、图注、视频旁白，都要过 R1 这一关。
