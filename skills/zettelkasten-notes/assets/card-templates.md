# 卡片模板集（card templates）

> 使用方法：按卡片类型复制模板填写，写完用 `scripts/check_card.py <文件>` 跑机械自检。
> 字段名与目录以库内本地规则文件为准；没有本地规则时用本文件的默认字段。纸笔用户可把 YAML 头换成卡角符号（如 ○ 草稿 / ◐ 已审 / ● 常青）。
> 规则依据：三类笔记见 `references/02-growth-logic.md`；写卡标准见 `references/03-card-writing.md`；连接与索引见 `references/04-connection-org.md`；六型分类见 `references/09-community-practices.md`。

## 0. 永久笔记四条硬标准（所有永久卡都过这一关）

**三年后测试**：想象三年后第一次看到这张卡。若"不太确定""好像懂又好像不懂"，或必须翻别的卡才懂 —— 不合格。

四个不能出现（坏例 → 好例）：

| 不能出现 | 坏例 | 好例 |
|---|---|---|
| 指示代词 | "这个观点很好" | "即时反馈是刻意练习区别于普通重复的关键因素——这个判断值得单独记一张卡" |
| 依赖来源 | "作者认为反馈的频率比质量更重要" | "反馈的频率比反馈的质量更重要。来源：文献笔记[[刻意练习-第78页]]" |
| 指代上下文 | "正如上文所说，反馈太慢会导致调整来不及" | "如果反馈太慢——比如一个月后才收到老师的批改——你在等待期间会反复重复错误的动作" |
| 模糊判断 | "即时反馈很重要" | "即时反馈的价值在于：它让'尝试—调整'的循环周期尽可能短，让错误在成为习惯之前就被纠正" |

字段：① 标题（直接陈述主张）② 正文（完整句子，一个想法）③ 连接（注明支持／反驳／补充／延伸）④ 来源（置末尾，不进入正文逻辑）。
篇幅：以"足以展开一个想法且不塞入第二个想法"为准；纸卡 A6 参照 100–200 字，写不下就拆成互联的多卡。

## 0.5 卡片 YAML 头（数字卡片的最小元数据）

```yaml
---
id: 202611011530          # 时间戳或卢曼式编号，二选一
status: draft             # draft → reviewed → evergreen；被推翻用 superseded
author: human             # human | ai | mixed | external
sources: [文献卡链接、原件路径或 URL]
updated: 2026-11-01
superseded_by:            # 可选：被哪张卡更替（status 为 superseded 时必填）
---
```

- 必填：`status`、`author`、`sources`（原创想法写 `["原创 YYYY-MM-DD"]`）。其余可选。
- 状态是给人看的成熟度信号，不是任务清单。`author: ai` 或 `external` 的卡只能是 draft，人审后才升级（见 `references/10-ai-collaboration.md`）。
- 闪念笔记可不加 YAML 头；文献卡、永久卡、修正卡、外部导入候选卡建议都加。

## 1. 闪念笔记（Fleeting Notes）

```markdown
# 闪念｜<一句话>
- 触发：<读到的段落/想到的念头/听到的话，写清场景>
- 我的反应：<为什么记它？可能指向什么问题？>
- 处理时限：<记录日期 + 2 天内处理>
```
处理完即弃：转化为文献卡／永久卡后删除，或转化不了就直接删。收件箱必须清空。

## 2. 文献笔记（Literature Notes，读书时记）

```markdown
---
status: draft
author: human
sources: [<原件路径或 URL>]
citekey:                  # 可选，如 smith2024
doi:                      # 可选
---
# 文献｜<一句话主题>
- 来源：<书名/文章/论文/数据集/访谈>，作者，页码/章节/时间戳
- 复述：<合上原文，用自己的完整句子重述一个核心想法；禁止照抄>
- 联想：<我同意/质疑/联想到什么？和我当前的哪个问题有关？>
- 原文锚点（可选）：<关键引文，≤2 行>
标签：#来源/<作者或主题>
```

## 3. 永久笔记（Permanent Notes，自足的知识单元）

```markdown
---
id: <编号>
status: reviewed          # 自己写完并自检通过；AI 起草的为 draft
author: human
sources: [[文献｜…]]
updated: YYYY-MM-DD
---
# <标题：直接陈述主张，如"反馈的频率比反馈的质量更重要">
<正文：完整句子展开一个想法，含机制或例子；不得出现"这个/它/上文/作者认为">

连接：<支持/反驳/补充/延伸/修正>：[[相关卡片]]
来源：<文献卡链接 或 "原创想法 YYYY-MM-DD">（置末尾）
```

## 4. 六型卡（按内容性质，标题前加性质关键词）

| 卡型 | 记什么 | 模板要点 |
|---|---|---|
| **概念卡** | 一个概念/理论的定义与解释 | 定义 + 不是什么（边界）+ 1–2 个例子 + 出处 |
| **观点卡** | 作者/专家的论断 | 主张 + 论据链 + 我的立场（同意/质疑/存疑及理由） |
| **方法卡** | 解决某类问题的步骤 | 适用场景 + 步骤 1/2/3 + **失效条件** + 出处 |
| **行动卡** | 具体策略与执行步骤 | 触发条件 + 动作清单 + 完成判据 |
| **案例卡** | 实例/故事 | 标题自带情境（"案例卡：X 事件中…"）+ 事件 + 印证/反驳了哪张卡 |
| **金句卡** | 原文金句 | 原句 + 出处 + **为什么打动我**（无注解的金句 = 未加工的收藏） |

```markdown
# 概念卡｜<概念名>
- 定义：<一句话>
- 不是什么：<常见误解/边界>
- 例子：<1–2 个>
- 出处：<来源>
标签：#概念卡 #<主题>
连接：[[…]]
```

## 5. 结构型笔记（一张卡承载一个知识群落）

用于把某一主题下已积累的卡片组织起来；是自下而上长出来的"组装图纸"，不是预先设计的目录。

```markdown
# 结构｜<主题名>
- 核心问题：<这个群落要回答什么问题？>
- 卡片地图：
  1. [[卡A]]（核心主张）
  2. [[卡B]]（支持论据）→ 与 [[卡C]] 构成对比
  3. [[卡D]]（反面案例）
- 缺口：<还缺什么论据/案例？下一步读什么？>
- 成熟度：<卡片数 / 是否达到立题门槛（≥10–20 张且彼此有论证关系）>
```

## 6. 项目笔记（一次写作/一个项目的临时容器）

```markdown
# 项目｜<产出物名称>
- 目标：<要交付什么，给谁看，何时完成>
- 主题：<本次从卡片盒打捞的哪个主题>
- 卡片清单：<本次调用的卡片编号/链接，按顺序>
- 进度：<待写 / 初稿 / 校对 / 定稿>
- 结项处理：<归档 + 有价值的想法回填为永久卡 + 本项目笔记丢弃>
```
作用：隔离（一个项目一个容器）、追踪（进度可见）、复用（结项回填卡片盒）。

## 7. 索引页（>10 张卡才建，是入口不是目录）

```markdown
# 索引｜<主题词>
- 核心卡（3–5 张）：[[卡A]]（核心主张）｜[[卡B]]（反例）｜[[卡C]]（方法）
- 关系标注：<A 支持 B；C 反驳 B 的边界情形>
- 相关索引：[[索引｜相关主题]]
- 未决问题：<这个集群还没想清楚什么？>
```
每月更新一次；每个索引只列 3–5 张核心卡，不要变成目录。

## 8. 修正卡（新证据推翻或限定旧卡时）

```markdown
---
id: <编号>
status: reviewed
author: human
sources: [<新证据的文献卡>]
updated: YYYY-MM-DD
---
# <新主张：直接陈述修正后的结论>
- 旧主张：[[旧卡]] 认为 <一句话复述旧主张>
- 新证据：<什么材料、什么发现>
- 修正：<推翻 / 限定适用范围 / 并存待定>，理由：<机制或证据>
连接：修正：[[旧卡]]；支持：[[…]]
```
旧卡处理：推翻 → 旧卡 `status: superseded`、`superseded_by: [[本卡]]`，原文保留；限定 → 旧卡不变，两卡互连；并存 → 两卡互连「矛盾」，在结构型笔记"未决问题"登记。规则见 `references/04-connection-org.md`「当新证据推翻旧卡」。

## 9. 外部导入候选卡（其他技能/工具导出、AI 对话摘录、剪藏）

```markdown
---
status: draft             # 一律草稿
author: external          # 或 ai
sources: [<原件路径或 URL>]   # 必填；没有来源的导入物退回
citekey:                  # 可选
doi:                      # 可选
imported_from: <导出它的工具或技能名>
imported: YYYY-MM-DD
---
# <候选主张（待人改写）>
<导入的要点，保持原样，不冒充复述>
- 建议连接：<旧卡> —— 理由：<…>（由人确认）
```
流程：只进收件箱 → 查重（重复则合并到旧卡）→ 人改写标题与至少一句正文 → 确认连接 → `author: mixed`、`status: reviewed`，移入主卡片盒。

## 10. 阅读→卡片化清单（配合 socratic-reading 使用）

```markdown
# 《书名》卡片化清单
- 检视层产出 → 结构件（一句话概括 + 全书纲要）
- 文献笔记 × N → 逐张转永久卡，或合并进既有卡
- 辩证笔记（我的质疑/共鸣）→ 延展笔记（原创卡）
- 每张新卡至少 1 条连接 + 关系标注
- 本书卡片 ≥10 张 → 考虑建索引页
```
