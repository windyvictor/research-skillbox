# AI 导师式精读协议（学术时空坐标 × 认知阶梯 × 苏格拉底式辩证 × 检验协议）

素材来源：王树义（公众号「玉树芝兰」）两篇文章——①《AI 加持下，啃论文能从「苦差事」变「探险」吗？》（2025-05-11）：白话讲解、公式细讲、图解可视化、交互式网页教程等讲解载体；②《如何用 AI 帮你把论文读透？》（2025-11-29）：三阶段"学术导师"设计。本版增补：证据四级标签、AI 核验协议、思路重建、检验协议（Steelman→脆弱假设→反例→一周验证→锁死→诚实注脚），依据见 skill README 来源表与 `web-research-methods.md` 调研纪要。

核心主张：从「让 AI 说人话」到「让 AI 当导师」是范式升级——AI 读论文的四大失败模式是缺乏学术定位、认知层次单一、缺乏批判性思维（当应声虫）、把 AI 当枪手而非帮手。对策是把解读组织为三个阶段、按需升级讲解载体，全程贯穿证据标签与引证/核验协议。

## 阶段一：学术时空坐标（Evidence-Based Contextual Matrix）

**强制规则：无检索，不定位。** 解读论文之前必须先检索相关文献（arXiv、Google Scholar、Semantic Scholar、webSearch 等），不能"就论文论论文"。挖掘三类文献：

| 方向 | 名称 | 要回答的问题 |
|---|---|---|
| 纵向·前 | 前导溯源（Roots & Foundations） | 这篇论文站在哪些前人肩膀上？前人做到什么程度、留下什么缺陷？正是这些缺陷催生了本文——由此知道论文"为什么这么说" |
| 纵向·后 | 后续演进（Legacy & Impact） | 发表后谁引用了它？是延续思路，还是批判甚至推翻了结论？由此看清"影响力轨迹"（刚发表的新论文此向可能为空，如实标注即可） |
| 横向 | 同期竞争场（Horizontal Competitors） | 同期还有谁在解决同一问题？技术路径有何不同、各自优劣是什么？不看竞争者就会被作者叙事"带着走"，误以为其方法是唯一正解 |

执行要点：

1. 每篇外部文献必须给出来源与可追溯链接，供用户点进原文自行核验；写入前执行下文「AI 核验协议」。
2. 前导溯源不止列理论名，要指出本文对经典理论做了什么"挑战"或"发展"；横向对比要落到"差异化定位"——本文靠什么区别于竞争者立足。
3. **不能只靠引用关系工具定位**：跨学科研究者可能独立提出相同模型而互不知情，引用网络会各成小团体、完全割裂。必须做跨关键词、跨学科检索（同义术语、方法名别名、相邻领域），寻找"孪生工作"。
4. **降级阶梯**：冷门/前沿论文可能检索不到足够外部资料——此时请用户提供已下载的相关文献，改在用户提供的文献子集内做定位，并注明"定位基于受限文献集"。

定位结论写入报告的"论文概览"与"研究空白识别"部分；定位不明（说不清回应什么问题、与谁竞争）本身就是一个批判性疑点。外部文献表述一律打 📄（原文原话）或 📚（已核验综述性结论）；推断打 🔎。

## 阶段二：认知阶梯（L1–L4 四层攀登）

学术研究有层次，讲解不能停在"说人话"。四层自下而上（四层梯度为经验结果，源自卓克老师课程，经作者多次尝试验证）：

| 层 | 名称 | 讲什么 | 达标标准 |
|---|---|---|---|
| L1 | 故事与直觉（Story & Intuition） | 用生活化类比讲清"作者遇到了什么难题、核心 Idea 是什么" | 非本专业大学生也能听懂核心思想 |
| L2 | 概念与逻辑（Concept & Logic） | 拆解系统输入输出，用逻辑链条（A → B → C）描述关键步骤，展示模块间交互 | 补上论文省略的中间步骤，不留逻辑黑盒 |
| L3 | 细节与技术（Detail & Implementation） | 具体模型、参数设置、工程 tricks、伪代码逻辑、数据预处理方式 | 想复现论文的用户能在此获得足够的工程细节指引（魔鬼在细节：参数不同结果天差地别） |
| L4 | 严谨与数学（Rigor & Mathematics） | 回归规范学术语言：逐行解析核心公式、解释每个符号的物理含义、理论边界条件、收敛性/完备性 | 达到"发表级理解深度" |

执行规则：

1. **信息等价性（Information Parity）**：读完 L1–L4 后，用户应获得等同通读全文的理解深度。不做"信息压缩"（把长的变短），而做"信息重构"（用更清晰有层次的方式传递论文全部信息）——不省略关键推导步骤、实验细节、参数设置。
2. **默认逐层上升，不自作主张停在底层**。用户只要求"讲讲"时先给 L1 定调，再按文献重要性（是否种子文献、是否要复现/改进）决定爬到第几层；用户停在低层而该文献是核心文献时，主动提示更高层还有什么。
3. **每层讲完做理解确认**再上升（让用户复述或回答检验性问题）——学习是主动建构，AI 降低门槛但不能替代思考。L3/L4 讲解后宜衔接「合书复述关」。
4. **层与层信息不混装**：类比是类比，公式是公式；类比失真处明说"类比在这里不成立，严谨表述是……"。
5. **证据标签**：讲解中引用的论文事实打 📄；外引打 📚；教学性类比与推断打 🔎；不确定处打 ❓。

## 阶段三：苏格拉底式辩证 + 思路重建 + 检验协议

讲完知识点后主动抛出发人深省的问题，并完成可执行检验（非敷衍的开放式提问）。

### 3.1 三种辩证方式

1. **思维实验（Thought Experiment）**：构建一个极端的边缘案例（Edge Case）或反例，挑战论文方法；借反例暴露论文的隐性假设与模型失效边界。
2. **方法论迁移（Methodological Transfer）**：揭示论文背后的通用思维模型，指导如何迁移到其他领域——"举一反三"是学术素养的体现。
3. **神来之笔（The 'Aha!' Moment）**：直接指出论文中最惊艳、最反直觉的一个点，并解释为什么精妙——论文最精彩处往往被作者轻描淡写地带过。

### 3.2 思路重建（标明推断）

不拿最终贡献当前提；只用背景、失败模式与观察，倒推「为什么会想到这个 idea」：

1. 失败模式（先前路线卡在哪）
2. 关键观察（触发转折的事实或约束）
3. 核心直觉（一句话；去掉方法名与缩写仍讲得清）

产出标注为 **🔎 基于证据的思路重建**，不得写成作者真实心理过程。报告中放在「两个终极问题」之前。

### 3.3 检验协议（顺序固定）

1. **Steelman**：先用最强合理解释重述作者论证（善意，PLOS Rule 7）。
2. **最脆弱假设**：从数据分布、监督/反馈信号、资源条件、评价协议四向找最脆支柱。
3. **反例四步**：选定 claim → 只改关键条件 → 公平对照 → 事先定义何为反证。
4. **一周最小验证计划**：D1–2 基线；D3–5 单变量；D6–7 复查。
5. **锁死效应**：结论多大程度上是方法逼出来的？换一类方法是否还成立？
6. **诚实注脚**：「本结论在 X 条件下不再适用，因为……」。

辩证与检验产出与 Step 3 批判性分析综合衔接：思维实验与反例记入批判清单；"神来之笔"写入精华点评；方法论迁移与新研究问题通向 Gap 与改进建议；一周计划写入读后六件套。

## 讲解载体阶梯（白话 → 公式细讲 → 图解 → 交互式教程 → 组会版可选）

认知阶梯管"讲到多深"，载体阶梯管"用什么介质讲"。同一层内容可以有多种载体，按用户困难点逐级升级（素材来源：2025-05 文）：

| 载体 | 适用场景 | 做法 |
|---|---|---|
| 白话概览 | 初步理解全文大意、建立感性认识 | "你用人话给我讲讲作者的研究设计、过程、结果，然后帮我找找这研究有什么不合理的地方"——**批判性要求内嵌在提示词里**，防 AI 顺着论文夸。白话只是"导览图"，概览不等于读懂 |
| 公式细讲 | 被数学公式卡住（最常见的"硬骨头"） | 接续对话："把所有出现的数学公式的含义，用刚才那种（通俗易懂的）风格解释一遍"；逐个公式梳理，每个符号给物理含义 + 生动的比喻/真实场景类比；看不懂随时追问展开 |
| 图解可视化 | 文字解释仍不够直观的复杂机制或公式 | 请 AI 用 SVG 或 Mermaid 可视化讲解；Mermaid 代码到 mermaid.live 渲染，可导出无限缩放的 SVG，精细到可放入正式报告。图后必须配文字逐参数说明，不能一张图了事 |
| 交互式教程 | 复杂机制需要"动手体验"才能理解 | 用 AI 生成纯前端 HTML 交互教程，提示词模板见 `assets/interactive-tutorial-prompt.md`（含批判嵌入句）；交付前用实际浏览器验证无报错 |
| 组会讲解版（默认关） | 用户明确要求讲给别人听 | 一页四列表：意义｜内容｜主要结论｜用自己的话讲 idea 以及我们能怎么做；或 8–16 页叙事大纲。AI 生成的数值必须回原文核对 |

执行规则：

1. **载体服务内容，不为炫技**：先判断卡点在"不懂大意"还是"不懂公式"还是"不懂机制"，再选载体；一句话讲清的不要画图，一张图讲清的不要做网页。
2. **批判前提不可省**：任何载体的讲解提示词都必须带上批判性要求（"找找不合理的地方"），否则 AI 只会顺着论文叙事拔高。
3. **模型选择**：严肃学术解读必须选低幻觉模型（可查幻觉排行榜核实），防止乱编内容误导研究；温度不宜过高（太高会放飞、牺牲客观准确），中等温度兼顾易懂与严谨。
4. **工具效率**：高频使用的解读提示词可做成预设快捷对话/模板反复重用，把"拖入论文"变成一步操作。

## 全程协议 A：证据四级标签

凡关键陈述（讲解、批判、重建、改进建议）必须标注：

- 📄 本文明确声称
- 📚 文献已有结论（已核验）
- 🔎 证据支持的推断
- ❓ 尚待验证的猜测

文献卡结论栏只收 📄/📚；🔎/❓ 进入联想或候选 idea。

## 全程协议 B：AI 核验协议（存在性 → 原文 → Full/Partial/No support → 未读不引）

适用于一切 AI 生成或检索得到的引用与主张（Oxford Bodleian + faithfulness 粒度）：

1. **存在性**：要求 DOI / URL / arXiv ID，用 Scholar 或出版目录核验条目真实存在。
2. **原文**：打开摘要或全文，核对 AI 复述是否漏掉局限与方法关键信息。
3. **支持粒度**：对每条断言标 **Full / Partial / No support**；Partial 必须拆句，不可整段当作 Full。
4. **未读不引**：未亲自查阅（至少核对到可定位原文）的文献，不得写入报告参考文献或卡片结论栏。
5. **披露**：若使用 LLM 辅助检索或摘要，在报告方法说明中简要披露；内容责任仍在执行者。

自动 faithfulness 指标在 Partial 上最弱，不可盲信分数代替人工核对。

## 全程协议 C：全源可核查引证（Universal Verifiable Citation Protocol）

凡涉及关键观点、数据或核心论述——无论来自用户提供的论文，还是检索到的外部文献——必须提供：**原文、精准定位（章节/页码/图表号）、中文翻译（外文时）、来源链接**。让整个过程可验证、可追溯：用户不必盲信 AI，随时可点进原文核对，发现解读有误可以纠正。

## 防"应声虫"与帮手定位

1. **主动要求批判，不等 AI 自发**。AI 训练机制偏向顺着文本"合理化"，不主动要求批判性分析时它会把普刊论文夸成权威。解读任何论文必须并行执行批判引擎（见 `critical-checklists.md`），至少回答：假设是否合理？证据是否充分？结论是否经得起推敲？先 Steelman 再对抗。
2. **夸奖与批评都要有证据**。说"好"要指出好在哪一步、比谁好；说"有问题"要给原文定位。无证据的褒贬一律不写。
3. **AI 是帮手不是枪手**。讲解保留思考空间：先让用户对关键步骤"猜答案"，再揭示论文方案；合书复述关由用户先说；AI 输出的解析不能被复制粘贴充当阅读笔记交差。
4. **不替作者圆场**。作者没写的不"合理化"补齐；论文缺 Limitations 章节时，把"未讨论局限"本身记为一条批评。

## 适用边界与降级汇总

- 输出天然较长（信息等价性所决定）：只想快速了解大概时走 L1/L2 简版并明确告知；深度掌握才走全流程。用户可在任务开始时选定目标层级与阅读目的。
- 检索工具不可用或冷门领域检索无果 → 降级为用户提供文献子集内定位，或标注"学术时空坐标未建立，分析受限"。
- 分析方法超出模型可靠能力（如专业统计方法）时，如实标注不确定（❓），不硬解。
- 难文可启用 QEC 预处理（约 20 分钟）再建坐标与讲解。
- 批量追踪可开「第一遍后暂停」，避免未经分流的全面精读。
