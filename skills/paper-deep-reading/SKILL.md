# 论文深度精读

将「读得快、读得全、读得狠、讲得透、落得成卡」合一：以阅读目的锁定深度，以三遍法控制阅读节奏，以结构化框架与 Claim–Evidence–Warrant 矩阵提取要素，以批判性思维引擎与可执行检验协议主动质疑每一篇论文，以 AI 导师式精读协议讲透核心文献，并以可选卡片盒导出把阅读沉淀为研究资产，最终产出可直接用于综述写作、选题与知识库入库的报告。

## 触发条件

满足以下任一条件即触发：

1. **学术文献输入**：论文链接命中学术平台域名（arXiv、IEEE Xplore、ACL Anthology、ACM DL、SpringerLink、ScienceDirect、PubMed、Semantic Scholar、Google Scholar、ResearchGate、bioRxiv、medRxiv、SSRN、CNKI、万方、维普、顶会/顶刊官网（如 NeurIPS、ICML、CVPR、ICLR、ACL、AAAI、CHI，以及各学科主要会议与期刊站点等）、doi.org 等）；本地 PDF/Word/Markdown/TeX/ePub 学术文档；粘贴文本含 ≥2 项学术结构标记（Abstract / Keywords / Introduction / References / DOI / arXiv ID）。
2. **结构化阅读意图**：速读/精读/深读/批判性阅读；要素提取（研究问题、方法、创新点、数据集、实验结果、局限等）；多篇对比与综述；论文质量评估、可信度分析、复现可行性判断；领域地图/入门扫文献；卡片盒导出/写文献卡；合书复述/读后六件套。
3. **学术延伸**：学位论文、技术报告、专利、标准的结构化阅读。

优先级：论文链接/文件 ＞ 学术文本片段 ＞ 意图描述。仅问概念术语（无文献输入）、纯翻译、非学术网页总结、改写润色降重 → 不触发。

## 阅读模式判定

根据用户意图、阅读目的与文献重要性选择模式（可主动询问，也可根据上下文默认）：

| 模式 | 适用 | 对应操作 | 达标标志 |
|---|---|---|---|
| L1 速读 | 判断相关性、快速分类、批量追踪 | 第一遍：标题/摘要/引言/标题层级/结论/参考文献扫描 + 5C + 价值粗分 + A/B/C 分流 | 能说出类型、贡献、是否值得再读，并给出分流 |
| L2 泛读 | 领域相关但非核心 | 第二遍：通读忽略证明细节 + 结构化提取 + Claim–Evidence–Warrant 矩阵 + 图表质疑 | 能向他人转述主旨与依据 |
| L3 批判精读 | 核心文献、评估、综述种子文献 | 第三遍：虚拟复现 + 思路重建 + 检验协议 + 批判引擎全清单 + 合书复述 + 读后六件套 | 能复述结构、指出隐含假设与弱点，并给出可执行验证计划 |
| 对比模式 | 多篇文献 | 每篇至少 L2，横向/纵向/方法论三维对比 | 产出对比矩阵与空白分析 |
| 领域地图 | 入门或开新方向 | 只读 Abstract、Intro（及高引综述全文）；派别表 + 方法演进图 + 精读候选 | 能答 2A/2B/2C（常用方法、派别、各派优缺点） |

**精力分配原则**：不是每篇论文都值得 L3。代表性/种子文献必须 L3；一般文献 L2；重复性、低相关文献 L1 即可。逐字逐句从头读到尾是阅读第一禁忌——永远先扫结构、再按需深入。新方向优先深读约 10 篇关键文，勿用海量浅扫代替精读配额（Nielsen）。

**可选开关**：
- **第一遍后暂停**（默认关；批量或例行追踪时可开）：做完 L1（含 A/B/C）后停下来问用户是否升档，再继续。
- **组会讲解版**（默认关）：用户明确要求时，在报告末追加一页四列表或 8–16 页叙事大纲。
- **可借鉴写作/图表栏**（默认关）：用户要求或精读写作范本时开启。

## 工作流

### Step −1：阅读目的（强制）

开读前选定阅读目的（四选一）；用户未说时按上下文推断，并在报告头写明「目的（推断）」：

| 目的 | 默认深度倾向 | 报告侧重 |
|---|---|---|
| ① 领域入门 / 找方向 | 领域地图或 L1→少量 L2 | 派别、演进、Future Work、精读候选 |
| ② 找 idea / 改进点 | L2→C 类升 L3 | 思路重建、脆弱假设、反例、新研究问题、候选 idea |
| ③ 为写作找依据（Related Work） | L1/L2，B 类为主 | 支持/反驳关系、可引用表述、对比矩阵 |
| ④ 复现或对比基线 | L2→L3 | Claim–Evidence、消融/基线/算力、Pineau 可复现快检、一周验证计划 |

难文可选 **QEC 预处理**（约 20 分钟，默认关）：专家/导师一句导读 + 检索评述与被引句 + 写预读摘要，再用 Question / Evidence / Conclusion 笔记骨架开读（Cal Newport）。

### Step 0：识别论文类型

| 类型 | 标识特征 | 分析重点 |
|---|---|---|
| 理工科 | 数学公式、实验方法、算法描述、数据集、baseline 对比 | 核心方法、数学原理、实验设置、消融实验 |
| 文科 | 理论框架、案例分析、政策讨论、论证结构 | 理论框架、论证结构、比较研究、实证方法 |

无法判定时默认理工科框架，并在报告注明。

同时检测导出关键词：出现 Word/docx 或 PDF 字样 → 报告末尾追加生成对应格式文档（命名 `文献批判性阅读报告_〈标题或简称〉_〈YYYYMMDD〉`）；未检测到则仅输出 Markdown。

### Step 1：确认范围与获取全文

- 用户未说明研究方向时先问一句，以便评估文献与其研究的关联度；已说明则在关联度、Gap 与候选 idea 中对照**用户自己给出的方向**，不预设、不绑定任何具体学科或课题。
- 多篇输入时**并行读取**：先把所有来源一次性取回，再统一做结构化提取，避免逐篇串行等待。

**取全文的按源路由**（同一篇往往有多种载体，按此优先）：

| 源 | 取法 | 要点 |
|---|---|---|
| 论文页（arXiv abs、IEEE、ACL、顶会、期刊页） | 浏览器读取正文 | 页面同时提供摘要页与 PDF/HTML 全文时，**优先全文**，摘要页只作元信息校对 |
| PDF 链接或上传的 PDF | PDF 解析取全文 | 公式、表格、脚注一并取出；扫描版需 OCR 或标注"图像版未能解析" |
| 上传的 Word / Markdown / TeX | 直接读文件 | TeX 源可核对公式与符号定义，优于 PDF |
| 粘贴文本 | 按学术结构标记判断完整性 | 缺 Methods / Results 时按"仅基于摘要"处理 |

**付费墙与不可达时的降级阶梯**（逐级尝试，每级记录失败原因）：出版商页面 → arXiv / bioRxiv / medRxiv / SSRN 预印本 → 机构库或作者主页 → ResearchGate 等作者自存版本 → 公开的 HTML 全文或代码仓库 README。全部失败才退回摘要。

- **红线：严禁仅凭摘要作答。** 全文不可得时在报告中明确标注"仅基于摘要"及受限原因（付费墙／仅摘要页／解析失败），所有摘要未提及的细节标注"需阅读全文"，绝不编造。
- **补充检索**：需要判断复现可行性时，检索作者主页、代码仓库、数据集公开页；只把实际找到的链接写入报告，找不到写"未发现公开实现"。

### Step 2：三遍式阅读与结构化提取

**第一遍（L1，全局扫描）**——回答五个 C（Keshav 三遍法），并可套用 PLOS 六问骨架（想知道什么 / 做了什么 / 为何那样做 / 结果示何 / 如何解释 / 下一步该怎样，含「你认为」的下一步）：

1. Category：什么类型的论文？
2. Context：与哪些工作相关？用了什么理论基础？
3. Correctness：假设看起来成立吗？
4. Contributions：主要贡献是什么？
5. Clarity：写得清楚吗？

任一 C 的答案存疑，记入待批判清单。

同步完成：
- **价值粗分**（李沐）：新意 × 有效 × 问题大小，各按 1 / 10 / 100 打分并附一句理由；乘积约 1000 可作为一流工作参考门槛。先区分「研究问题」（试前不知是否 work）与「工程问题」（试前已知会 work）。
- **A/B/C 分流**：A = 不相关或指标不可信 → 归档；B = 有启发但方法不同 → 留 Related Work；C = 与自己方向匹配 → 精读候选。报告末固定输出「分流：A/B/C ＋ 一句理由」。

若开启「第一遍后暂停」，此处停下征求用户是否升 L2/L3。

**第二遍（L2，结构化提取）**——严格基于全文，对每篇提取（无法获取的标"未提及"）：

- 通用维度：标题、作者（第一作者+等）、年份、研究问题（1 句）、研究方法（2–3 句）、创新点（1–2 个）、局限性（优先引用原文 Limitations；无则标"论文未明确讨论"）、文献综述质量（广度/深度/批判性）。
- 理工科附加：核心方法（含模型/算法名）、数学原理（LaTeX）、实验设置（baseline、消融）、数据集（来源/规模/预处理）。
- 文科附加：理论框架、论证结构（论点-论据-逻辑性）、案例分析、比较研究、政策建议、实证研究（数据来源/分析方法/结果解释）。
- **Claim–Evidence–Warrant 矩阵**（必做）：每行含 claim｜证据（实验图/表或定理/引理）｜warrant（为何证据推出主张）｜对照设计｜覆盖范围｜是否充分｜作者声称 vs 证据实际支持。理论型论文改用 **Claim–Theorem–Assumption**：查每条 claim 由哪个定理支撑，以及定理假设是否在论述/数值实验中真正满足。
- **消融–基线–算力三连问**：Baseline 是否当代强基线？拿掉核心模块后指标下降是否合理（单变量）？提升是否主要靠堆参数/算力？
- **可复现性快检**（Pineau）：勾选假设与算法设定、数据划分与预处理、超参范围与最终配置、跑次与误差棒、算力、代码/复现命令是否可得。
- **图表专项质疑**：坐标轴标注合理吗？刻度是否被操纵？有误差棒吗？样本量足以支撑结论吗？每个图表是否真对应其声称的结论？拆解后回链方法节核对。
- **论证一致性核对**：Abstract / Introduction / Conclusion 三处对照 claim，检查是否一致、是否前后矛盾。

**第三遍（L3，批判精读，仅核心文献）**——虚拟复现 + 思路重建 + 检验协议 + 批判引擎：

- 设想自己是作者，用同样的假设重新实现该工作；对比虚拟实现与原文，识别隐藏假设、被遗漏的引用、实验或分析技术的潜在问题。
- 逐节"猜答案"：读到问题陈述先自己想解法，再看作者方案；读到结果先自己推结论，再看作者解读。
- **思路重建**（独立小节，标明推断）：不拿最终贡献当前提；产出「失败模式 → 关键观察 → 核心直觉」；用一句话写出 intuition，去掉方法名与缩写后仍讲得清；全文标注为「基于证据的思路重建（🔎）」，不得写成作者真实心理过程。
- **检验协议**（顺序固定，详见 `references/cognitive-ladder.md` 与 `critical-checklists.md`）：
  1. **Steelman**：先用最强合理解释重述作者论证（善意）。
  2. **最脆弱假设**：从数据分布、监督/反馈信号、资源条件、评价协议四向找出最脆支柱。
  3. **反例四步**：选定一条 claim → 只改关键条件 → 保留公平对照 → 事先定义何为反证。
  4. **一周最小验证计划**：前 2 天跑通基线，中间 3 天验证单一变量，最后 2 天复查。
  5. **锁死效应**：结论多大程度上是方法逼出来的？换一类方法是否还成立？
  6. **诚实注脚**：补一句「本结论在 X 条件下不再适用，因为……」。
- **必须加载 `references/critical-checklists.md`**，逐项执行质疑清单（含证据四级标签说明、CEW、消融/基线/算力、可复现快检、检验协议、读后六件套、反模式），把每一条命中的质疑写下来。
- **合书复述关**：合上原文，用自己的话复述核心方法链条（按论文类型取用：数据流、关键方程、损失函数、实验流程，或主要论点与论证步骤），并定位卡在哪里。执行方式：先请用户复述，再对照指出遗漏；用户不愿时可跳过，但须在报告注明「未经复述检验」。
- **读后六件套**（L3 必做；L2 至少前 3 项）：①一句话核心 idea；②方法流程或核心论证/模型框图；③一条关键假设及失效场景；④一个反例；⑤一周最小验证计划；⑥一个新研究问题。

**必须加载 `references/cognitive-ladder.md`**，按其中的"AI 导师式精读协议"执行：

1. **阶段一·学术时空坐标**（L2 及以上必做）：**无检索，不定位**——解读前先检索三类文献并写入报告：①前导溯源；②后续演进（新论文此向为空时如实标注）；③同期竞争场。不能只依赖引用关系工具，要跨关键词、跨学科检索。检索无果的降级方案见 reference。
2. **阶段二·认知阶梯 L1–L4**（用户要求"讲讲/讲透/讲解这篇论文"时）：按"故事与直觉 → 概念与逻辑 → 细节与技术 → 严谨与数学"四层逐层攀登；遵守信息等价性；载体按卡点升级（公式细讲 / SVG·Mermaid / `assets/interactive-tutorial-prompt.md` 交互教程）。讲解提示词必须内嵌批判性要求；选低幻觉模型，温度不宜过高。
3. **阶段三·苏格拉底式辩证 + 检验协议**（L3 精读收尾）：思维实验、方法论迁移、神来之笔，并执行上列 Steelman→脆弱假设→反例→一周验证→锁死→诚实注脚。
4. **全程·证据四级标签 + AI 核验协议 + 全源可核查引证**：凡关键陈述打 📄/📚/🔎/❓；AI 生成的引用与主张走「存在性→原文→Full/Partial/No support→未读不引」；附原文 + 精准定位 + 中文翻译（外文时）+ 来源链接。
5. **防"应声虫"**：批判性分析必须主动并行执行；夸奖与批评都要有证据；讲解保留用户思考空间。

### Step 3：批判性分析综合（核心交付）

将 Step 2 记录的质疑整理为四个层次；**每条结论必须带证据标签**（📄本文明确声称 / 📚文献已有结论 / 🔎证据支持的推断 / ❓尚待验证的猜测）：

1. **问题层**：问题定义清晰吗？简化/扩展形式是什么？问题真的重要吗？是研究问题还是工程问题？
2. **方法层**：假设合理且被明确陈述吗？方法与研究问题匹配吗？有无更简单/更新的替代方法？适用范围与限制是什么？**锁死效应**如何？
3. **证据层**：数据足以支撑假设吗？测量有效且可信吗？有无未考虑的替代解释？结果是否被夸大？CEW/消融/基线/可复现快检结论如何？补 **诚实注脚**。
4. **贡献层**：比已有工作好在哪？文章的精华在哪？**新意×有效×问题大小**三维打分（附理由）；如果我来解决这个问题，会怎么做？

然后做**研究空白识别**：读综述结尾的"未来方向"、读局限性章节、对比多篇找矛盾与不足 → 提炼可操作的研究机会。对每个空白按"选题意义四标准"与"可控性五问"评估，并定位开拓性/推进性选题。

**改进建议**：针对上述不足给 1–3 条可落地的改进，遵循奥卡姆剃刀与第一性原理；每条建议写清改哪一步、为什么有效、代价是什么，并打 📄/📚/🔎/❓。不确定则宁可不写。

**批判性阅读的立场要求**：二次文献阅读必须探寻多元观点；发现观点被驳倒时如实修正。识别论文研究视角（理论/思维/批判），用于对比与综述归纳。

### Step 4：输出报告

**必须加载 `references/report-templates.md`**，按其中模板输出完整 Markdown 报告，包含：报告头（阅读目的、价值粗分、A/B/C）、论文概览表、逐篇深度分析（含 CEW/思路重建/检验协议/批判四层）、综合对比矩阵（多篇时）、研究空白与机会、读后六件套、可直接使用的论文表述、GB/T 7714-2015 参考文献列表。

可选追加：组会讲解版；可借鉴写作/图表栏；文献笔记五要素。

**综述场景补充**（多篇对比且用户目标是写综述时）：以"综述四问"组织归纳；结构按"三写法"选型；述评比约 7:3。

**与后续检索衔接**（批量时）：末尾输出「下一步检索关键词」（含同义词与跨学科别名），供继续检索或文献管理回流；C 类升档建议写清。

### Step 5：卡片盒导出（可选；用户要求或已配置卡片盒/知识库时）

若用户已配置卡片盒或知识库（如 zettelkasten 类规范，或其他自有笔记库），则生成草稿卡片（默认 `status: draft`，待用户审）：

1. **文献卡**（写入路径与字段名以用户卡片盒/知识库规范为准）：五栏——问题设定｜方法与关键假设｜带条件的结论｜实验｜局限。**结论栏只收 📄/📚**，并写成立条件与页码/章节；🔎/❓ 进入联想或 Comments，不进结论栏。写卡必须合书复述后用自己的话，禁止大段摘抄。若规范要求 `raw/` 只读、AI 不改不删原文，必须遵守。
2. **对比卡 / 问题卡草稿**（放 research 区）：多篇比较或读后新研究问题时生成；关系链接标「支持 / 反驳 / 延伸」。
3. **想法卡**：只给**候选**列表；**必须用户明确批准后**才正式写入；未经查新一律标「候选 idea」。

导出前若存在卡片校验脚本（如 `check_card.py`），按用户规范运行；失败则修正后再交付。

### 领域地图模式（第五模式）

适用：入门或开新方向。流程：

1. 收集约 30–40 篇候选（可含近 3 年高引综述）；对多数篇**只读 Abstract 与 Introduction**（综述可读全文 Future Work）。
2. 回答 **2A / 2B / 2C**：最常被引用的方法有哪些；方法分成哪些派别；各派特色与优缺点（从各篇 Intro 收集对其他派别的批评）。
3. 产出：①派别表（含互相批评）；②方法演进 Mermaid 图（→ 表示改进，★ 表示里程碑）；③精读候选清单（建议配额：先深读约 10 篇关键文，再浅扫扩展）。
4. 可选「机会主义种子集」：请专家给 3–5 篇各浅读约 20 分钟，再沿近 5 年顶会外扩。

本模式不要求每篇 L2；升档精读时回到主工作流。

## 质量控制红线

- 严禁仅凭摘要作答；全文不可得必须显式标注。
- 绝不编造：指标数值、实验细节、作者/年份/标题必须来自原文；未提及一律标注。
- 局限性优先引用原文 Limitations；作者没写的不要替作者"合理化"。
- 指标不可比时（不同数据集/任务）明确标注"评估条件不同，不可直接对比"。
- 学科侧重分明：文科核对论证严谨性；实证研究核对数据与分析方法；理论/算法文核对假设、等价性与离散化/实现是否匹配声称。
- 批判必须基于文本证据；不得为批判而批判，也不得因文章知名而放弃质疑；先 Steelman 再对抗，禁止 Strawman。
- **证据四级标签**：批判、重建、改进建议中的每条结论必须带 📄/📚/🔎/❓。
- **AI 核验协议**：①要求 DOI/URL；②用 Scholar/目录核存在性；③打开原文核对摘要与局限；④每条 AI 断言标 Full / Partial / No support（部分支持须拆句）；⑤未亲自查阅的文献不得写入参考文献。
- 全源可核查引证：原文 + 精准定位 + 来源链接；外部文献核对后再写入。
- 所有引用使用 GB/T 7714-2015 顺序编码制。
- 想法卡未经用户批准不得正式入库；`raw/` 区（若存在）AI 只读。

## 失败处理

- 单篇无法访问/读取 → 注明具体 URL 与失败原因，跳过并继续处理其余论文；全部失败 → 停止并请求用户提供可访问来源。
- 上传文件无法读取 → 说明是格式不支持还是文件损坏，请用户重新提供或换格式。
- 单篇提取维度不足 3 个 → 对比矩阵标注"信息不足"，并建议用户提供全文后重跑。
- 论文类型无法判定 → 默认理工科框架，并在报告开头注明。
- 报告生成失败 → 先返回 Markdown，末尾附注失败原因。
- 卡片导出校验失败 → 保留报告正文，附草稿与校验错误，不强制写入。
